# 需求工作台

本文档用于逐步收集需求。当前内容记录已经确认的第一版方向，以及后续仍需讨论的开放问题。

## 项目目标

搭建一个简单但完整的轻量电商下单系统，用来学习从本地开发到容器化、再到 Kubernetes 部署的完整链路。

## 学习目标

已确认的核心学习目标：

- Go 工程结构和模块管理。
- go-zero 的 HTTP API、配置和代码生成。
- gRPC 服务间通信。
- PostgreSQL 数据建模和访问。
- Docker Compose 本地集群。
- Kubernetes Service、DNS、Ingress、Deployment、ConfigMap、Secret。

后续可扩展学习目标：

- etcd 服务注册与发现，用于 Docker Compose 阶段理解 go-zero 服务发现。
- Redis 缓存、幂等或分布式锁。
- Dockerfile 镜像构建。
- 日志、指标、链路追踪。
- 单元测试、集成测试和接口测试。

## 已确认业务主题

第一版业务主题为轻量电商下单系统。它天然适合拆成多个微服务，也能覆盖常见后端系统问题：

- 用户服务。
- 商品服务。
- 订单服务。
- 库存服务。
- 支付模拟服务。
- 网关 API 服务。

## 第一版功能范围

### 用户

- 用户注册。
- 用户登录。
- 查看当前用户信息。

### 商品

- 创建商品。
- 查询商品列表。
- 查询商品详情。
- 商品上架和下架。

### 库存

- 初始化库存。
- 查询库存。
- 扣减库存。
- 回滚库存。

### 订单

- 创建订单。
- 查询订单详情。
- 查询用户订单列表。
- 取消未支付订单。

### 支付

- 创建模拟支付单。
- 模拟支付成功。
- 查询支付状态。

## 核心业务闭环

第一版端到端链路：

```text
用户注册/登录
  -> 查询商品
  -> 创建订单
  -> order-rpc 调 inventory-rpc 扣减库存
  -> order-rpc 创建订单
  -> payment-rpc 创建模拟支付单
  -> 模拟支付成功
  -> order-rpc 更新订单状态为 paid
  -> 查询订单详情
```

需要重点体现：

- 库存不能超卖。
- 重复支付不能重复改变状态。
- 未支付订单可以取消，取消后库存回滚。
- API 层不直接访问业务数据库。
- 服务间错误需要返回清晰业务错误。

## 待确认问题

### 技术范围

- 是否从第一阶段就使用 Docker Compose？
- Kubernetes 使用 kind、minikube，还是只产出 YAML？
- 是否加入消息队列，比如 Kafka、RabbitMQ 或 NATS？
- 可观测性是否用 Prometheus + Grafana + Jaeger？

### 业务范围

- 是否需要前端页面，还是只做后端 API？
- 登录鉴权先使用简单 token，还是引入 JWT？
- 商品创建和上下架是否需要管理身份？

### 学习优先级

请给下面目标排序：

- 快速跑起来。
- 深入理解 go-zero。
- 深入理解 gRPC。
- 深入理解 Docker 和 Kubernetes。
- 深入理解微服务治理。
- 深入理解可观测性。
- 深入理解测试和 CI。

## 非目标

初始阶段不追求：

- 真实支付接入。
- 高并发压测级别性能。
- 复杂权限模型。
- 多租户。
- 完整前端应用。
- 生产级安全合规。
