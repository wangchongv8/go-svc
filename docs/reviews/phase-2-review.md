## 高优先级问题

### 1. 手动修改了 goctl 生成文件，`make gen` 会破坏 `/healthz`

状态：已修复。

文件：

- `apps/gateway-api/internal/handler/routes.go:1`
- `apps/gateway-api/internal/handler/routes.go:37`
- `apps/gateway-api/gateway.api:39`

问题：

- `routes.go` 明确标记为 `Code generated by goctl. DO NOT EDIT.`。
- 当前 `/healthz` 路由是在 `routes.go` 中手动追加的。
- `gateway.api` 中没有声明 `/healthz`。
- 一旦执行 `make gen`，`routes.go` 会被重新生成，`/healthz` 很可能丢失。

建议：

- 把 `GET /healthz` 正式写入 `apps/gateway-api/gateway.api`。
- 重新生成 go-zero 代码。
- 避免手动维护 `routes.go` 这类生成文件。

### 2. 业务错误被映射为 HTTP 500，并暴露原始 RPC 错误文本

状态：已修复。

文件：

- `apps/user-rpc/internal/logic/loginlogic.go:29`
- `apps/user-rpc/internal/logic/loginlogic.go:34`
- `apps/user-rpc/internal/logic/getuserlogic.go:29`
- `apps/gateway-api/internal/handler/user/loginhandler.go`
- `apps/gateway-api/internal/handler/user/getuserhandler.go`

问题：

- `user-rpc` 直接返回普通 `error`。
- gRPC 层把这些错误变成 `codes.Unknown`。
- HTTP 层通过 `httpx.ErrorCtx` 返回 `500 Internal Server Error`。
- 实测错误响应为 `text/plain`，例如：

```text
HTTP/1.1 500 Internal Server Error

rpc error: code = Unknown desc = invalid password
```

这会让“用户不存在”“密码错误”“用户名重复”这类业务错误变成服务端故障，也不利于后续 API 统一错误格式。

建议：

- RPC 层使用 `status.Error` 返回明确 gRPC code，例如：
  - `InvalidArgument`: 参数错误。
  - `AlreadyExists`: 用户名重复。
  - `NotFound`: 用户不存在。
  - `Unauthenticated`: 密码错误。
- gateway 层统一把 gRPC code 映射为 HTTP 状态码和 JSON 错误响应，例如：
  - `InvalidArgument -> 400`
  - `Unauthenticated -> 401`
  - `NotFound -> 404`
  - `AlreadyExists -> 409`
  - 其他错误 -> 500`
- 为这些负向路径补测试，至少覆盖登录失败、查询不存在用户、重复注册。
